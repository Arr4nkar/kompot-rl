Четыре стакана компота¶

Q-learning и SARSA без отрицательных наград¶

Практическая работа №4 · «Интеллектуальные системы и технологии»

Цель: научить агента уравнивать объёмы в четырёх стаканах за минимальное число поднятий. Из одного поднятого стакана можно налить сразу в несколько других.

Ноутбук содержит математическую модель, описание алгоритмов, реализацию обоих методов в соседнем модуле, эксперимент и проверку результата. Запуск: Run → Run All Cells. В JupyterLite всё обучение выполняется в браузере; первый запуск загружает Python и библиотеки из сети.

Для полного опыта используйте MODE = "full"; для быстрого — "quick". Режим "saved" открывает измеренный полный результат без нового обучения. Уже выполненные ячейки позволяют прочитать работу без запуска.

1. Математическая модель и состояния¶

Принимаем допущения: одинаковые стаканы, без потерь, без внешней воды; вместимость каждого $C=6$, общий объём $V=12$, объёмы целочисленные. Эти числа выбраны для модели и являются её допущениями. Например, единица может соответствовать 50 мл.

$$s=(v_0,v_1,v_2,v_3),\quad v_i\in\{0,\ldots,6\},\quad \sum_i v_i=12.$$

Четыре переменные, из которых три независимы. Стаканы различимы. Целевое состояние $(3,3,3,3)$.

$$|S|=[x^{12}](1+x+\ldots+x^6)^4 =\binom{15}{3}-4\binom{8}{3}=231.$$

230 неготовых стартовых состояний и одно целевое. При непрерывных объёмах состояний было бы бесконечно много. Сумма объёмов должна делиться на четыре, иначе точное равенство в выбранной целочисленной сетке недостижимо.

2. Действия и кодирование¶

Один шаг — одно полное поднятие и разлив. Выбираем источник $i$ и объёмы $(q_1,q_2,q_3)$ для остальных стаканов в порядке их номеров.

$$k=49q_1+7q_2+q_3,\quad a=342i+k-1.$$

$i\in\{0,1,2,3\}$, $q_j\in\{0,\ldots,6\}$, $k>0$. Код действия — целое число от 0 до 1367. В конкретном нетерминальном состоянии допустимы только 54–86 кодов: нельзя перелить больше содержимого источника или переполнить получателя. Маска задаёт ограничения физики; в ней остаются ходы, удаляющие от цели.

Пример: из $(6,2,2,2)$ поднять первый стакан и налить по единице в остальные. Это действие с кодом 56, результат $(3,3,3,3)$, одно поднятие. Какой стакан сейчас в руке, хранить не нужно: действие завершается до следующего состояния.

3. Награда, штрафы и окончание эпизода¶

$$r(s,a,s')=\begin{cases}1,&s'=(3,3,3,3),\\0,&\text{иначе.}\end{cases}$$

Отрицательных наград нет. За промежуточное «правильное» поднятие — 0, за достижение цели — +1.

Чтобы предпочитать меньше поднятий, максимизируем дисконтированный доход:

$$G_0=\sum_{t=0}^{L-1}\gamma^t r_{t+1}=\gamma^{L-1},\quad\gamma=0.9.$$

Успех за одно поднятие даёт 1, за два — 0.9, за три — 0.81. Просто недисконтированная сумма наград равна 1 при любом успехе и не различала бы длину пути.

Окончание: равенство объёмов (terminated=True). 30 поднятий — технический предел попытки (truncated=True), а не достижение цели. Отдельного штрафа за прерывание нет. В обновлениях после прерывания сохраняется bootstrap; после настоящего завершения он равен нулю. Поэтому технический счётчик не меняет марковское состояние из четырёх объёмов.

4. Два метода обучения¶

Q-learning (off-policy): $$Q(s,a)\leftarrow Q(s,a)+\alpha[r+\gamma\max_b Q(s',b)-Q(s,a)].$$

SARSA (on-policy): $$Q(s,a)\leftarrow Q(s,a)+\alpha[r+\gamma Q(s',a')-Q(s,a)],$$ где $a'$ действительно выбрано ε-жадной стратегией.

Общие параметры: $\alpha=0.5$, $\gamma=0.9$, начальная ε=0.6, конечная ε=0.05. ε линейно уменьшается за первые 80% обучения, затем постоянна. Q-таблицы изначально нулевые. При обучении равные максимумы выбираются случайно; при проверке — первый допустимый код, чтобы оценка была воспроизводимой.

Ни один метод не получает правильные действия или число необходимых поднятий. Ниже — фактически выполняемый общий цикл; различается формирование целевого значения.

def train(env, method="q_learning", seed=0, progress=None):
    if method not in ("q_learning", "sarsa"):
        raise ValueError("method must be q_learning or sarsa")
    cfg = env.config
    q = new_q(env)
    # Equal starting states for paired seeds; exploration gets its own RNG.
    starts = np.random.default_rng(seed).choice(env.starts, size=cfg.episodes)
    rng = np.random.default_rng(seed+100_000)
    distances = shortest_distances(env)
    history = {"return": [], "raw_reward": [], "lifts": [], "epsilon": [], "checkpoints": []}
    history["checkpoints"].append({"episode": 0, **evaluate(env, q, distances)})
    started = perf_counter()
    for episode, start in enumerate(starts):
        fraction = min(episode/max(1, int(cfg.episodes*0.8)-1), 1.0)
        epsilon = cfg.epsilon_start + fraction*(cfg.epsilon_end-cfg.epsilon_start)
        sid = int(start)
        action = epsilon_greedy(q[sid], epsilon, rng)
        solved = False
        for step in range(cfg.max_steps):
            nxt = int(env.next_states[sid][action])
            solved = nxt == env.goal_id
            reward = float(solved)
            if solved:
                target = reward
                next_action = None
            elif method == "q_learning":
                target = reward+cfg.gamma*float(q[nxt].max())
                next_action = None
            else:
                next_action = epsilon_greedy(q[nxt], epsilon, rng)
                target = reward+cfg.gamma*q[nxt][next_action]
            q[sid][action] += cfg.alpha*(target-q[sid][action])
            if solved:
                break
            sid = nxt
            action = (epsilon_greedy(q[sid], epsilon, rng)
                      if next_action is None else next_action)
            # At time-limit truncation bootstrap is retained: this is not a goal.
        lifts = step+1
        history["return"].append(cfg.gamma**(lifts-1) if solved else 0.0)
        history["raw_reward"].append(float(solved))
        history["lifts"].append(lifts)
        history["epsilon"].append(epsilon)
        if (episode+1) % cfg.eval_every == 0 or episode+1 == cfg.episodes:
            checkpoint = {"episode": episode+1, **evaluate(env, q, distances)}
            history["checkpoints"].append(checkpoint)
            if progress:
                progress(method, seed, checkpoint)
    history["seconds"] = perf_counter()-started
    return q, history

5. Независимый точный минимум¶

Для каждого состояния строим все физически допустимые переходы и считаем кратчайшее расстояние до цели обратным BFS. Этот алгоритм используется только для оценки, не для обучения.

Есть и доказательство: каждый стакан выше среднего обязательно нужно поднять, иначе его объём не уменьшится. Достаточно поднять каждый такой стакан один раз и разлить его избыток по дефицитам. Значит, минимум равен числу стаканов выше среднего. Во всех 231 состояниях проверяем совпадение этого результата с BFS.

6. Эксперимент¶

Полный режим: 200 000 эпизодов × 5 seed × 2 метода. Проверка каждые 5000 эпизодов. У парных seed одинаковая последовательность стартов; генераторы стартов и разведки разделены. Начальные состояния выбираются равномерно из 230 нецелевых вариантов.

Каждая проверка — жадная стратегия на всех 230 стартах без обучения. Это проверка освоения конечной среды, не обобщение на невиденные объёмы. Сравниваем успех, оптимальность, число поднятий и дисконтированный доход. Неуспех учитывается как 30 поднятий, а не удаляется из среднего.

Сохранённый полный эксперимент доступен независимо от выбранного режима. Быстрый режим имеет меньший бюджет, поэтому его результаты могут отличаться.

def results_table(data):
    lines = ["| Метод | Успех | Оптимум | Поднятия | Доход | AUC дохода |",
             "|---|---:|---:|---:|---:|---:|"]
    for row in summary_rows(data):

                     f"{row['optimal_rate']:.2%} ± {100*row['optimal_rate_std']:.2f} п.п. | "
                     f"{row['mean_lifts_capped']:.3f} ± {row['mean_lifts_capped_std']:.3f} | "
                     f"{row['discounted_return']:.4f} | {row['auc_return']:.4f} |")
    for key, label in (("random", "Случайный выбор"), ("oracle", "Точный оптимум")):

        lines.append(f"| {label} | {row['success_rate']:.1%} | {row['optimal_rate']:.2%} | "
                     f"{row['mean_lifts_capped']:.3f} | {row['discounted_return']:.4f} | — |")
    display(Markdown("\n".join(lines)))

9. Выводы и ограничения¶

В сохранённом полном опыте оба метода достигают равенства во всех состояниях. Q-learning: 99.39% ± 0.58 п.п. оптимальных решений; SARSA: 94.70% ± 1.21 п.п.. Среднее число поднятий — 1.693 и 1.741 при точном минимуме 1.687. Демонстрационный Q-learning с seed=0 оптимален во всех 230 стартах.

При выбранном бюджете и общих параметрах Q-learning лучше по итоговой оптимальности и среднему доходу. Возможное объяснение — SARSA учитывает разведочные действия в целевом значении, а ε остаётся положительной. Это интерпретация результата, а не доказательство универсального превосходства. Раннее обучение у SARSA на части интервала проходит быстрее — это видно на кривых.

Не утверждаем сходимость после фиксированного числа эпизодов: α постоянная, ε не исчезает, оптимальность не равна 100% во всех запусках. Полосы показывают только разброс между пятью seed. Параметры выбраны после пробных прогонов без отдельного поиска оптимальных настроек каждого метода.

Дискретизация ограничивает точность объёмов. При других вместимостях и общем объёме меняются множества состояний и действий; табличное обучение нужно повторить.
